# 词条反馈（实验功能）

每个词条显示点赞、点踩和评论数量。赞踩互斥，再点所选项可以取消。评论默认折叠，展开后加载最新 30 条，再按需查看更早的评论。评论为纯文本，最长 2000 字，匿名发布后立即显示。

反馈对应词条的固定 ID。修改正文保留反馈；删除词条后反馈不再展示，恢复同一词条 ID 时重新显示。备份恢复正文不会重置赞踩或评论。

## 浏览器凭证

浏览器首次加载反馈时，服务端签发随机凭证，保存在本站 HttpOnly Cookie 中，有效期一年，每次访问续期。数据库只保存凭证的 SHA-256 摘要。同一浏览器对一个词条只有一条赞踩记录，由数据库联合主键保证。写入只接受本站 Origin 和有效凭证。

不采集设备指纹或 IP，不公开浏览器标识，评论记录也不保存发布者标识。清除 Cookie、使用无痕窗口或更换浏览器会产生新凭证。这个机制用于保留选择和减少重复投票，不保证一人一票。

同一凭证的赞踩操作间隔至少 300 毫秒，评论发布间隔至少 10 秒。限流和写入在同一个 D1 事务内完成。

## 维护评论

在项目目录运行以下命令。维护者密钥放在本机 `.env.cloudflare` 的 `MAINTENANCE_TOKEN` 中，该文件不提交到 GitHub。可用 `CF_WIKI_URL` 指定网站地址。

```powershell
# 词条 ID 就是条目链接中 # 后面的部分。
npm run comments -- list s-b0c6c09e10fc
npm run comments -- hide 12
npm run comments -- restore 12
```

`list` 返回最近 30 条评论及其编号，`hide` 立即从公开页面移除，`restore` 可恢复误删。删除只标记隐藏，原文保留在 D1。更早的评论可请求 `GET /api/sections/<词条ID>/comments?before=<上一页最后的评论ID>`。

维护接口为 `DELETE /api/comments/<评论ID>`（隐藏）与 `PATCH /api/comments/<评论ID>`（恢复），使用现有维护者 Bearer 密钥及本站 Origin。前端不存储维护者密钥。

## 备份

新的四小时快照使用 `sufe-wiki/v2`，同时包含正文、赞踩记录和评论（包括已隐藏评论），仍只允许维护者下载。反馈按行保存在 `wiki_snapshot_feedback`，避免整站评论塞入一个数据库字段。旧的 v1 快照仍可下载和恢复正文；浏览器凭证不进入快照。
